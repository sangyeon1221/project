Ragxiv
arXiv 논문을 찾아 읽고 답해주는 RAG 어시스턴트입니다. 현재 가지고있는 노트북 CPU만으로 돌아가게끔 설계했습니다.

질문을 입력하면 arXiv에서 관련 논문 한편을 검색해 고르고, PDF를 받아 인덱싱한 뒤 그 내용에 근거해서 답합니다. 클라우드 API를 쓰지 않기 때문에 질문 내용이나 다루는 논문이 외부로 새나가지 않습니다.

4학년 졸업작품으로 만들었습니다. 이후 ScholarMind로 이어지는데, 논문 출처를 Semantic Scholar로 바꾸고 신뢰도 필터, BM25+벡터 하이브리드 검색, 다중 소스 PDF 확보, 답변 스트리밍을 추가한 버전입니다.

동작 방식
질문이 들어오면 먼저 후속 질문인지 판별합니다. "방금 논문 요약해줘" 같은 질문이면 새로 검색하지 않고 이미 인덱싱된 논문을 그대로 씁니다. 키워드 매칭으로 대부분 걸러내고, 애매한 경우에만 LLM에 물어봅니다.

새 주제라면 이렇게 진행합니다.

1. LLM이 질문을 arXiv 검색용 영어 키워드로 바꿉니다
2. arXiv에서 최대 10편을 가져옵니다
3. LLM이 초록을 읽고 한 편을 고릅니다 — 왜 골랐는지도 화면에 표시됩니다
4. 해당 PDF를 받아 텍스트를 뽑고 1,000자 단위로 쪼개 FAISS에 넣습니다
5. 질문과 가까운 청크 5개를 찾아 LLM에 넘기고, 답변과 출처를 함께 보여줍니다
구성
추론	Ollama + EXAONE 3.5 2.4B (로컬, CPU)
임베딩	intfloat/multilingual-e5-small (384차원)
검색	FAISS IndexFlatIP
논문	arXiv API
PDF	PyMuPDF
UI	Streamlit
만들면서 겪은 것들
임베딩 모델을 바꿨습니다. 처음엔 BGE-small-en을 썼는데, 한국어로 질문하면 검색이 엉뚱한 본문을 가져왔습니다. 영어 전용 모델이라 한국어 벡터가 사실상 의미 없는 값이 됐던 겁니다. LLM은 한국어를 이해하는데 검색 단계에서 막히고 있었던 셈입니다. multilingual-e5-small로 바꾸니 한국어 질문과 영어 본문이 같은 공간에서 비교됩니다. 둘 다 384차원이라 FAISS 쪽은 손댈 게 없었습니다.

다만 e5는 질문에 query: , 문서에 passage: 접두사를 붙여야 합니다. 빠뜨려도 오류는 안 나는데 검색 품질이 조용히 떨어져서 놓치기 쉽습니다.

arXiv 호출 방식을 고쳤습니다. 처음엔 결과를 순회하면서 매번 쉬도록 되어 있었는데, 10편 가져오는 데 30초가 넘게 걸리고 타임아웃이 났습니다. 네트워크 요청 직전에 한 번만 3초 쉬도록 바꿨습니다. arXiv의 요청 제한은 지키면서 속도는 크게 줄었습니다.

PDF에서 나오는 유니코드 노이즈를 걸러냅니다. 논문 PDF를 텍스트로 바꾸면 사설 영역 글리프나 베트남어 성조 부호 같은 게 섞여 나오는데, 소형 모델에 들어가면 출력이 깨집니다. 허용 문자 범위를 정해두고 그 밖은 공백으로 치환합니다.

FAISS는 IndexFlatIP를 씁니다. 임베딩할 때 L2 정규화를 하기 때문에 내적만 계산해도 코사인 유사도와 같은 값이 나옵니다. 근사 없이 정확한 최근접 이웃을 찾으면서도 CPU에서 충분히 빠릅니다.

답변이 비면 두 번 더 시도합니다. 짧은 프롬프트로 재시도하고, 그래도 안 나오면 논문 초록을 그대로 보여줍니다. 소형 모델이 가끔 빈 문자열을 뱉는 문제 때문에 넣었습니다.

실행
Ollama가 설치되어 있어야 합니다.

git clone https://github.com/sangyeon1221/ragxiv.git
cd ragxiv
pip install -r requirements.txt
ollama pull exaone3.5:2.4b
터미널 두 개가 필요합니다.

ollama serve          # 1번 터미널
streamlit run app.py  # 2번 터미널
i7-1355U + 16GB RAM에서 개발했습니다. GPU는 필요 없지만, CPU 추론이라 답변 생성에 수십 초가 걸립니다.

한계
논문을 한 번에 한 편만 인덱싱합니다. 새 논문을 넣으면 이전 것은 지워지기 때문에, 여러 논문을 비교하는 질문에는 답할 수 없습니다.
답변 품질은 2.4B 모델의 한계를 그대로 따릅니다. 프롬프트 지시를 놓치는 경우가 있습니다.
EXAONE 3.5는 비상업 라이선스입니다. 학술·개인 용도는 허용되지만 상업적 사용에는 LG AI Research와 별도 계약이 필요합니다.
